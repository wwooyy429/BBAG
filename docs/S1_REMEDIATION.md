# S1-001 修复与复审边界

2026-10-31 的独立审核对准确提交 `f5c07d2b878c3b7e9f122bcf064ef45589d9aaa7` 给出 CHANGES_REQUIRED、工程 FAIL，1 项 P1 阻断 S1-001。原审核报告、回执、输入与失败证据保留，S0 的批准及合并结论不变。此文说明修复，不能作为独立关闭记录。

## 问题与修复

原 LabelRule 固定下一期开盘入场、H 个会话后开盘退出，却允许任意 price_field。审核的合成输入中，入场/退出 open 均为20，close为20→40，volume为300→900；程序分别保存0%、100%、200%的成熟标签，后两者与声明开盘事件不一致。保守的日线available_at和成熟延迟不能使错误字段成为开盘价格。

当前阶段只支持 `price_field="open"`，保持字段显式，不提供未定义的别名或收盘执行事件。LabelRule在构造及重校验时拒绝其它值，S1Config和LabelResult中的嵌套规则沿用同一契约；compute_labels在读取报价前重新验证传入规则，包括绕过正常构造而修改的实例。CLI在加载配置时拒绝，退出2，不生成成功run。合法open路径仍按实际配置计算，未静默忽略price_field。

## 兼容影响与验证

S1 Schema版本仍为1.0，报价字段域收紧为常量open；LabelRule、S1Config、LabelResult三份Schema同步。原先被错误接受的close、volume或别名标签配置现在无效，调用者必须提供有开盘语义的open字段；不能把其它字段重命名来声称已有行情语义校验。S1仅使用合成面板，真实数据映射仍由后续授权范围实现。其它字段可以继续用于因子公式，S0契约保持。

回归覆盖原合成反例、契约和嵌套配置、直接服务的绕过构造/修改、CLI拒绝与无成功产物，以及open的零收益、独立有理数价格/超额价格收益、成熟前一微秒和精确成熟时点。原24行因子与24行标签手算夹具不修改；原有成熟、数值、来源、交付及Schema检查继续保留。实际命令、退出码、JUnit和统计只在提交后绑定新SHA的开发报告与原始证据中登记，不在本文件预填通过结果。
