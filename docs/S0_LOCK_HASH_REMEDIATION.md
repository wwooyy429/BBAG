## 缺陷与修复规则

S0 打包器原先未检查 `verification.dependency_lock_sha256`，错误的 64 个零、缺字段及 `NOT_A_SHA256` 均可退出 0 并生成包。原正式交付包中的锁哈希正确；反例使用明确标记的污染证据副本，不表示原开发证据造假。

本轮仅改变 S0 证据接纳边界：

- 字段必须为字符串，按采集器的规范格式使用小写 64 位十六进制 SHA-256；拒绝空白、大小写变体、缺失及其他 JSON 类型，不做隐式转换。
- 字段必须等于脚本所在源码根目录的 `requirements.lock` 原始字节摘要，不读取调用者工作目录中的同名文件。
- 完整 CLI 另核对工作副本锁与准确 HEAD 提交中的锁字节摘要一致，即使 Git 的 assume-unchanged 或 skip-worktree 隐藏本地差异也不能接纳。
- 任一锁检查失败都退出 2，发生在新交付目录、源码 archive 和 ZIP 创建前，保留已有输出。
- 正确锁仍可打包；S1 原有锁哈希校验与三类拒绝对照保留。

锁依赖版本、公式、标签、独立标准答案和研究参数均未改变。合成协议继续为 ENGINEERING_TEST / DRAFT；配置校验不构成经济批准或真实数据访问授权。
