# BBAG 给 Codex 的开发报告

历史规划交接版本。阶段 0 实施后的开发结果和审核材料，以 `deliverables/stages/S0/<实现 commit SHA>/` 中提交后生成的报告、固定源码及原始证据为准；本文件不表示当前实现状态。

编制日期：2026 年 10 月 31 日。

**使用方式：**将本报告及 `references/` 一并交给负责实现的 Codex。当前整理与打包不启动实现；后续取得开发任务后，首个任务仅做 S0。S1 至 S7 是完整路线，不是自动执行清单。

## 目的、基线与范围

建设 GPT 提出经济假设、QuantConnect Research 计算因子、LEAN 验证交易、GPT Work 独立审核的研发系统。目标是可复现、可追溯、有预算的研究闭环，允许结果为支持晋升、拒绝或证据不足。

交接基线是四份规划文档，尚无系统实现、平台运行或阶段验收证据。本报告和压缩包是交接材料，不能作为功能、测试或收益已经通过的证明。

先读 [项目说明](references/README.md)、[完整路线](references/ROADMAP.md)、[验收规范](references/ACCEPTANCE.md)、[路径用例](references/FLOW_ACCEPTANCE.md)。接入实际项目后还需读取适用的 `AGENTS.md` 和已有实现；发现版本冲突时明确记录，以最新确认的项目协议统一口径。

首版采用单一市场、频率、数据适配器和评价协议，美股日频价量截面因子作为初始方向。具体股票池、预测期、调仓、成本、风险和预算在 S0 固定。基本面、文本、多资产、复杂前端和真实资金自动部署留作扩展。

业务运行链路为：

```text
研究章程、预算与测试封存 → 时点数据与历史股票池
→ GPT 假设和 FactorSpec → 公式、时序、计算审计
→ Research 快筛 → LEAN 组合与成本回测
→ 受限优化及最终配置开发复验 → 冻结 → 独立最终测试
→ 有效通过：前向模拟与监控；有效拒绝或证据不足：归档
```

Research 与 LEAN 的开发结果进入研究记忆，再反馈给 GPT；配置变化返回受影响的审计、Research、LEAN 复验。最终测试及其派生信息隔离于开发循环。

## 分阶段实施目标

### S0：研究协议与工程骨架

**依赖：**无。将要求转成可读取、可校验的配置，先明确数据可用、信号、下单、最早成交、退出及标签成熟的时间关系。固定开发区、最终测试区、预算、停止、冻结和晋升条件。

**交付：**最小 Python 工程与运行入口、依赖记录、项目规则、样例配置及 DataSpec、FactorSpec、LabelSpec、ExecutionSpec、EvaluationSpec、ExperimentRecord、ReleaseManifest 接口；定义编号、哈希、证据和交接目录。

**验收：**有效样例可校验并生成实验清单；缺必填项、时间冲突可明确拒绝；输入输出关联版本；测试隔离可落实到后续接口。此阶段不实现因子数值和平台调用。

### S1：确定性因子引擎与审计

**依赖：**S0。实现最小算子白名单、受限表达式和语法树审计，检查字段、类型、窗口、参数、复杂度和回看期。特征与未来标签计算分离，固定缺失、除零、常数和窗口不足的行为。

**交付：**共享因子与标签服务、批量与逐期接口、手写基准、手算样本及审计记录。

**验收：**独立手算一致；未来数据扰动不改变历史因子；截断计算一致；非法未来引用被拒绝；批量与逐期结果在登记容差内相符。

### S2：平台适配、时点数据与股票池

**依赖：**S0、S1 数据接口。接入真实小样本，按历史日期形成股票池，处理证券身份、更名、退市、公司行动、时区、日历及复权。日期权限由程序执行，开发接口不能查询封存区。

**交付：**QuantConnect 适配器、持久任务状态、标准数据面板、历史成分、数据质量与版本、缓存及访问边界测试。

**验收：**字段可追溯原始值；历史成员和复权正确；越界访问被阻止；真实平台小任务完成；故障、未知提交、重复消息与恢复有证据。使用平台返回的项目、任务编号；先列出项目，不猜编号。区分接受、编译、运行、结果和评估完成；按当前接口规则等待结果，未知状态先核实，实际重试照实记账。

### S3：单因子 Research 评估

**依赖：**S1、S2。先运行固定传统基准，构造与真实入场和退出匹配的标签，按日期滚动切分，约束标签成熟、跨边界标签和预处理拟合范围。

**交付：**研究入口、标准评估器、滚动配置、覆盖与区分度、IC/RankIC、分层、暴露、换手、相关性和分期报告；保存原始序列、对照、失败及实验台账。

**验收：**同版本可重放；关键指标可独立复算；无时间越界；对重叠标签、时间相关和随机对照采用预登记统计解释。工程完成不要求显著正 IC，Research 报告不代替可交易验证。

### S4：LEAN 可交易闭环

**依赖：**S3。复用因子逻辑，连接股票池、信号、目标持仓、风险、订单、成交、退出和净值。明确预热、调仓、重叠持仓、资金占用、未成交及不可交易处理。

**交付：**基准 LEAN 算法、费用/点差/滑点/成交约束及适用融资借券成本、风险配置、订单和净值原始记录、计算对账与压力报告。

**验收：**收盘后信号不无条件按同日收盘成交；Research 与 LEAN 同时点数值一致；成本和风险限制真实生效；净值可复算；完成真实平台基准全流程。S4 是基础系统里程碑。

### S5：GPT 假设生成与开发反馈

**依赖：**S0 至 S4。S5.1 从章程、字段、算子、文献和开发记忆生成机制、方向、期限、竞争解释和失效条件，支持研究员输入；S5.2 编排审计、快筛及必要回测；S5.3 保存、检索成功和失败并生成下一轮提案。

**交付：**GPT 接口、结构化候选、编排器、预算和修复上限、研究记忆、候选谱系、恢复记录及一次完整反馈迭代。

**验收：**非法字段、未来信息、超深公式和越界请求被程序拦截；数值来自真实计算；预算生效；重复消息不重复计入，重试费用不遗漏；经济逻辑变化登记新配置。全部候选被拒也可通过工程验收。自改进指研究记忆和实现迭代，不包含训练 GPT 权重。

### S6：受限探索、组合增量与最终复验

**依赖：**S5。S6.1 规范化表达式并检查结构、因子值绝对相关与收益相关；S6.2 固定简单模型比较基准、加候选及删除候选；S6.3 固定因子集再有限优化模型，统一日期、股票池、成本和风险。记录全部配置、参数、方向、预处理及选择分支；DSR/PBO 等只按登记协议诊断，不反复作为搜索目标。

**交付：**搜索协议、完整候选谱系、消融和组合报告、模型比较、统计诊断、预算与停止记录，以及 S6.4 复验证据。

**验收：**变化可归因、取负号不绕过去重、无跨区选择、结果可重放、到预算正常停止。无合格候选就归档开发批次，不强制冻结。

**S6.4 是冻结前硬门槛：**唯一清单关联源码、数据、股票池、公式/算子、预处理、特征顺序、标签/评价、模型训练、组合、风险、交易与成本。修改后使受影响旧证据失效，返回相应审计、Research、LEAN；无影响且版本匹配的证据可注明理由复用。最终组合必须有自身含成本 LEAN、对账及必要压力证据，单因子结果不能替代。任务接受、运行中、失败、版本错配或证据缺失不能通过；复验也计预算，不能借最终测试补做开发验证。

### S7：冻结、独立测试与前向运行

**依赖：**S6.4。S7.1 核对证据并保存不可变发布清单；S7.2 受控执行冻结流程及固定基准；S7.3 按晋升条件前向模拟并对账；S7.4 监控数据、成熟标签表现、成本、风险、衰减，演练恢复、切换和回退。

**交付：**冻结包、独立审计结论、访问历史、前向日志、信号与订单对账、监控和恢复记录。

**验收：**版本、数据和历史模型时点合法；晋升、归档与技术恢复分支正确；运行能力有可追溯演练，经济证据单独判定。模拟成交不能单独证明真实容量；观察不足如实保留经济证据不足状态。

## 不可绕过的控制规则

固定模型核对冻结工件和清洗器。滚动模型冻结初始工件、训练和更新准入规则；允许按预登记时间边界生成、通过就绪校验的新工件，逐次记父版本、训练截止和启用时间。禁止把最终权重或清洗器回灌历史。训练规则、参数选择或特征处理实质变化，需新版本和开发复验。

评估执行有效性单独记录：`VALID` 才能按协议产生 `SUPPORT`、`REJECT`、`INCONCLUSIVE`。代码、数据或版本错误记 `ERROR`，必要任务未完成记 `INCOMPLETE`，无法确认执行记 `UNKNOWN`；后三者经济结论保持 `NOT_EVALUATED`，核查或恢复，不能冒充统计证据不足。

只有有效 `SUPPORT`、必需工程/平台项通过且部署符合冻结包，候选才进入 `ECONOMIC_VALIDATION`。有效 `REJECT` 或 `INCONCLUSIVE` 归档，不自动调参重试。`ENGINEERING_TEST` 使用独立基准或夹具，可以验收运行能力，不改变被拒候选状态，不将演练收益当经济证据。

最终数据、指标、图表、排名、解释、评审意见、调参建议及摘要留在独立审计区；禁止进入开发记忆、生成提示、检索、摘要和常规导出。编排器只接收编号、执行有效性和允许动作等最小控制信息，亦不写入研究记忆。负责人披露留痕；结果用于修改或选择后，登记该区间已用于决策。代码修复不能删除访问历史或重新命名“未见测试”。保留模型、提示和文献快照；日期过滤不能消除 GPT 预训练历史知识污染。

## 实施、路径测试与 Work 交接

每期按“固定需求和验收→实现自测→冻结版本→交接→Work 独立复验→修复→复验”推进。缺少前置验收，不将依赖阶段标为通过。变更后重验受影响部分，保留原缺陷和原结果。

模块测试之外落实 F01–F08：正常晋升；Research/LEAN 失败反馈；最终拒绝归档；有效证据不足归档；最终配置变化与旧证据失效；最终派生内容隔离；工程演练与合法滚动更新/非法更新拒绝；技术异常和恢复。合成或受控成功结果只验证测试命名空间内的逻辑；平台集成需要真实任务，经济结论需要真实独立数据。

交接提供源码快照或固定提交、配置/数据/环境版本、接口和阶段范围、复现步骤、许可允许的样本与手算答案、原始日志/指标/订单、平台编号、全部配置与费用、已知限制。凭据独立提供，不装入报告。Work 先核实可用文件、执行环境与平台工具；无能力的项标未验证，不只审读 Codex 总结。

分别报告工程 `PASS/FAIL/INCOMPLETE`、平台 `PASS/FAIL/NOT_RUN/NOT_APPLICABLE`、经济证据及执行有效性；每项注明 `EXECUTED/STATIC_ONLY/NOT_RUN`、原始证据及未验证原因。只有实际独立验收才登记 `ACCEPTED`，本包没有任何阶段已通过的断言。
