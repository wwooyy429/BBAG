# GPT 审核包使用说明

本包用于 GPT 或 GPT Work 对 BBAG 进行独立审核。先阅读 [审核报告与任务要求](GPT_AUDIT_REPORT.md)，再查看 references 中的规范和 templates 中的结果模板。

[用户提供的原始流程图](references/WORKFLOW_REFERENCE.png) 用于核对节点和连线；S6.4、异常处理和派生信息隔离按完整规范检查。SOURCE_MANIFEST.json 记录来源与快照哈希，manifest.json 记录本包文件校验值。

本次提供的是审核任务报告、规则和模板，尚未提供已开发系统的源码、运行环境、原始测试数据、日志或真实 QuantConnect 结果。收到本包后，可以核查规划与证据要求；不能仅凭规范出具功能或平台集成通过结论。

## 建议的审核任务

将下段与对应阶段的固定版本源码和运行证据一起交给审核者：

> 请按本包 GPT_AUDIT_REPORT.md 对我指定阶段的固定版本独立审核。先核实被审版本、文件、环境及平台工具，再设计并执行边界、反例和独立数值复核。使用 templates/AUDIT_RESULT_TEMPLATE.md 逐项记录实际执行、仅静态检查或未运行，分别给工程、平台、经济证据和执行有效性结论。缺少源码、环境或原始证据时，明确记录 INCOMPLETE 或 NOT_RUN，不用阅读开发总结代替独立运行。生产代码修复交回 Codex，审核者在独立副本中新增测试和报告。最终测试和派生摘要只按受控协议使用，不进入开发记忆。固定模型和滚动模型按各自冻结规则核验。

## 每次审核还需要提供

| 材料 | 用途 |
|---|---|
| 阶段编号及准确源码版本 | 明确审核对象与范围 |
| 配置、环境、依赖和数据版本 | 复现执行条件 |
| 原始输入及少量可手算样本 | 独立计算和反例测试 |
| 运行、安装和测试步骤 | 实际执行验证 |
| 日志、指标序列、订单与平台任务 | 核验开发报告与实际结果 |
| 已知缺陷和未验证事项 | 确定补验和复验条件 |

日常交接只提供开发区的合规材料。S7.2 最终审计所需的封存材料另行通过受控通道提供，不打入开发用包。

文件校验清单只确认包内版本与完整性，不证明实现或因子有效。
