# BBAG 阶段验收与开发交接规范

Codex 负责实现、自测和修复，GPT Work 对固定版本执行独立验收。验收从 S0 开始贯穿各阶段；最终历史测试在 S7.2 按预登记协议执行。

## 角色和操作边界

| 角色 | 工作内容 | 输出 |
|---|---|---|
| 项目负责人 | 固定研究目标、预算、范围及风险条件，处理协议变化 | 研究协议与版本化决策 |
| Codex 开发 | 按阶段实现、运行开发测试、提供证据、修复问题 | 固定代码版本和阶段交接包 |
| GPT Work 审核 | 独立核对规范、构造反例、复算数值、执行验收 | 绑定版本的审核报告与测试证据 |
| 确定性评估程序 | 执行指标、预算、时点和晋升规则 | 原始计算结果及状态 |

独立审核通过固定版本、独立样本和参考计算实现。Work 在审核副本中新增测试与报告，生产代码修复交回 Codex。审核聊天首先核实文件、代码执行环境和平台工具；缺少能力的项目标为未验证。

## 每阶段的固定流程

1. 固定本阶段目标、接口、范围和验收用例。
2. Codex 实现并执行相关开发测试，保存原始输出。
3. 冻结代码与配置，生成带版本清单的交接包。
4. Work 核验材料与运行环境，独立执行验收和必要的参考计算。
5. Work 给出缺陷编号、复现证据、影响与未验证项。
6. Codex 修复并保留原始缺陷记录，新增或更新有意义的回归测试。
7. Work 复验新版本，注明旧结论的适用范围和变化。
8. 当前阶段所需的工程和集成条件达成后，进入下阶段；经济晋升另按研究协议判定。

实现期间可继续独立开发任务。接口或基础能力未通过时，依赖它的阶段不应标记为已验收。

## 三种结论分别记录

| 维度 | 状态 | 判断依据 |
|---|---|---|
| 工程实现 | PASS、FAIL、INCOMPLETE | 接口、计算、配置、恢复和可复现性是否达到阶段标准 |
| 平台集成 | PASS、FAIL、NOT_RUN、NOT_APPLICABLE | QuantConnect 或 LEAN 上的实际执行证据 |
| 因子经济证据 | SUPPORT、REJECT、INCONCLUSIVE、NOT_EVALUATED、NOT_APPLICABLE | 有效评估是否支持晋升；技术异常或未完成时保持未评估 |

接口模拟、源码阅读和 Codex 日志不能被登记为平台独立重跑。数值计算正确但候选无效时，工程可以通过，经济证据记为 REJECT。前向观察样本不足时，运行能力可验收，经济证据保持 INCONCLUSIVE。

测试项同时记录执行方式：EXECUTED 为实际执行，STATIC_ONLY 为仅静态检查，NOT_RUN 为未执行。每个 NOT_RUN 项写明原因与补齐证据的方法。

## 评估有效性与候选晋升

执行有效性独立于工程、平台和经济结论。适用的评估任务记录以下状态：

| 执行有效性 | 含义 | 允许的经济结论或动作 |
|---|---|---|
| VALID | 所需输入、运行、结果和版本校验完整有效 | 根据预登记条件产生 SUPPORT、REJECT 或 INCONCLUSIVE |
| ERROR | 代码、数据或版本校验发生错误 | NOT_EVALUATED，核查并保留错误与访问记录 |
| INCOMPLETE | 已知必要任务或结果尚未完成 | NOT_EVALUATED，等待或按协议恢复 |
| UNKNOWN | 无法确认提交或执行状态 | NOT_EVALUATED，核实已有任务，避免盲目重复提交 |

INCONCLUSIVE 仅表示有效评估后的经济证据不足。技术故障、缺必要输入和未完成任务不归为统计证据不足。没有评估任务的阶段可记为不适用。

冻结前必须取得 S6.4 对准确最终配置的开发复验证据。公式、模型、预处理、组合或交易配置变化后，相关旧证据失效；最终组合有自身的含成本 LEAN 结果。固定模型比对工件，滚动训练核对同一训练规则及合法的逐窗口模型，不能把未来训练结果用于历史。

候选前向经济验证须同时满足：最终执行有效、相关必需工程和平台项通过、经济结论为 SUPPORT、部署配置遵循被审冻结包。固定模型的工件和清洗器须匹配冻结清单；滚动模型允许按冻结规则合法生成且通过就绪校验的新工件，须记录谱系、训练截止时间与启用时间。改变训练规则、参数选择或特征处理需建立新版本并返回受影响的开发复验。REJECT 与 INCONCLUSIVE 均归档该轮结论；NOT_EVALUATED 进入技术核查或等待，不允许晋升。

工程功能演练使用独立的 ENGINEERING_TEST 记录及固定基准或夹具编号；候选前向经济验证使用 ECONOMIC_VALIDATION 及候选发布包编号。用例中的受控成功结果只能验证测试命名空间内的分支，不得写入正式研究候选的经济结论或晋升记录。工程验收可以通过基准演练完成，被拒候选的状态不变。

## 阶段状态

| 状态 | 含义 |
|---|---|
| PLANNED | 目标和范围已登记 |
| IN_PROGRESS | 实现进行中 |
| READY_FOR_REVIEW | 固定版本和交接包准备完成 |
| CHANGES_REQUIRED | 审核发现需要修复或补证据的项目 |
| ACCEPTED | 当前阶段必需条件已验收，并绑定准确版本 |

版本改变后，受影响的验收项需要重新检查。阶段的 ACCEPTED 不等于候选因子通过经济晋升，也不等于允许真实资金部署。

## 交接包内容

| 文件或材料 | 必须包含的信息 |
|---|---|
| 版本清单 | 阶段、代码提交或内容哈希、配置哈希、环境及数据版本 |
| 阶段规范 | 目标、范围、接口、依赖、验收用例和预登记门槛 |
| 源码 | 完整固定快照，或能够取得该固定提交的说明 |
| 复现说明 | 环境准备、运行命令、输入、输出位置和预计资源 |
| 测试样本 | 合成数据或许可允许交付的样本，标明来源和用途 |
| 标准答案 | 少量能够独立手算的期望值和计算过程 |
| 运行证据 | 原始日志、指标序列、订单、成交、净值及错误记录 |
| 平台清单 | 项目与任务编号、运行配置、代码及可取得的引擎版本 |
| 已知限制 | 缺陷、未执行检查、权限或数据限制及补验方案 |
| 实验记录 | 候选谱系、全部配置、选择过程、执行次数和预算消耗 |

封存最终测试的原始数据、指标、图表、排名、逐候选结果、解释、评审意见及调参建议不进入开发用交接包。派生摘要继承其来源的隔离属性，禁止经研究记忆、生成提示词、检索索引、自动摘要或常规导出进入开发循环。凭据通过执行环境提供，交接包中只列明所需权限。

## 重点独立测试

| 测试 | 适用阶段 | 预期行为 |
|---|---|---|
| 小样本手算 | S1、S3、S4 | 因子、标签、IC、收益与费用和独立答案一致 |
| 未来数据扰动与截断 | S1 至 S7 | 修改未来数据不影响过去因子，截断前已形成值保持一致 |
| 字段披露与修订 | S2 及数据扩展 | 按真实可用时点和允许的数据版本取值 |
| 历史股票池 | S2 至 S7 | 历史成员、更名、退市和流动性筛选正确 |
| 成交和标签时点 | S3 至 S7 | 信号之后才可成交，标签与实际入场和退出匹配 |
| 标签成熟与预处理 | S3、S6、S7 | 训练时只用已成熟标签，拟合不越过允许区间 |
| 批量与逐期计算 | S1、S4 | Research 与 LEAN 同时点共享计算结果一致 |
| 费用和净值重算 | S4、S7 | 原始订单与成交能解释净值和费用 |
| 成交及风险限制 | S4、S7 | 规则超限时真实阻止或调整交易行为 |
| 非法候选与预算 | S5、S6 | 非法字段、未来引用、超深公式和超预算请求被拒绝并留痕 |
| 冗余与候选计数 | S5、S6 | 取负号不绕过相关检查，经济逻辑改变进入新配置 |
| 超时与重复结果 | S2、S5、S7 | 未知状态可恢复，结果不重复计入，避免盲目重复提交 |
| 封存测试访问 | S2 至 S7 | 开发接口和生成代理不能越过日期权限 |
| 模型时间一致性 | S6、S7 | 历史时点不能加载未来训练完成的模型 |
| 最终配置开发复验 | S6.4、S7.1 | 变更后旧证据失效，最终组合自身的审计、Research 和 LEAN 证据匹配才可冻结 |
| 晋升分支与演练用途 | S7 | 仅有效 SUPPORT 候选进入经济前向验证，归档候选不能改标签部署 |
| 最终信息的派生隔离 | S2、S5、S7 | 最终指标、图表和解释的摘要同样不能被开发检索或导出 |
| 停止与恢复 | S5 至 S7 | 预算耗尽、中断和失败有明确状态与恢复记录 |
| 版本切换与回退 | S7 | 仅使用就绪版本，切换失败能恢复已验证的旧版本 |

随机因子和打乱标签等统计对照使用预登记的样本量、重复次数和解释规则，不能要求每次随机结果恰为零。独立参考计算尽量避免直接复用被审指标函数。

## 完整路径验收

除模块测试外，还须执行 [流程路径验收用例](FLOW_ACCEPTANCE.md)。用例覆盖正常晋升、开发失败反馈、最终拒绝、最终证据不足、最终配置变化、隔离防绕过、工程演练及技术异常恢复。

每条用例独立登记源码、配置、数据或夹具版本、执行方式、运行用途、原始证据和实际结论。合成输入与接口模拟只能验证相应控制逻辑；QuantConnect 集成通过另需真实任务和结果证据。用例规范的编写不代表这些用例已执行。

## Codex 阶段任务模板

> 读取本阶段规范、适用的 AGENTS.md、研究协议和前置阶段结论。仅实现当前阶段范围。先核实接口与验收标准，再完成代码、相关开发测试和原始运行记录。所有指标来自实际运行；配置与经济逻辑变化完整登记。最终配置按 S6.4 复验，缺必要证据不得冻结。交付准确版本、源码、复现步骤、证据和已知限制。最终测试及其派生内容保持隔离，工程演练与候选经济验证分别记录。生成可供 GPT Work 独立验收的交接包，并列明本阶段必需条件的完成状态。

## GPT Work 阶段审核模板

> 对提供的固定版本和阶段规范独立验收。先核验源码版本、文件、运行环境及 QuantConnect 或 LEAN 工具。自行设计边界与故障测试，并从原始输入独立复算关键数值。检查最终配置复验、晋升门槛、派生信息隔离和适用的完整路径用例。生产代码的修复交回 Codex；新增审核测试与报告保存于审核副本。标明实际执行、仅静态检查和未执行，保留原始证据。按工程实现、平台集成和经济证据分别给结论，另记评估执行有效性及运行用途。封存最终测试仅在 S7.2 的受控协议下执行，不为日常调试提前访问。

## 最终测试和新版本

Work 可以作为最终测试的受控执行者；数据访问和结果披露仍需由实际权限与程序约束。最终测试结果一旦用于修改或选择候选，该区间即标注为已用于开发决策。

最终审计区保存原始结果和全部派生内容。编排器只接收发布包编号、任务编号、执行有效性和允许动作等最小控制信息，用于执行归档、技术恢复或合规晋升；这些信息不写入开发记忆。负责人可以按预登记协议查看审计材料，披露对象、内容和用途须留痕。

工程缺陷在最终评估中被发现时，保留原始测试和失败记录，修复后明确哪些证据已被观察。不得把同一区间重新命名为未见测试。新版本的独立经济证据需要相应的新数据或预先固定的未使用评估区间。

预登记协议允许的同冻结配置基础设施重试须保留所有原始任务和访问记录。修复若改变公式、模型、预处理、训练规则或交易配置，产生新版本并返回受影响的开发复验；不得借技术重试覆盖原经济结论或删除披露历史。
