# BBAG GPT 独立验证审核任务报告

历史规划交接版本。阶段 0 实施后的待审核对象和复现材料，以 `deliverables/stages/S0/<实现 commit SHA>/` 的固定源码、开发报告和审核请求为准。旧规划包中的状态不得代替新版本验收。

编制日期：2026 年 10 月 31 日。

本文是交给 GPT Work 或其他独立审核者的任务说明、验收计划和待填写结论模板，不是已执行的系统审计报告。当前交付只有项目规划与规范，没有能够证明系统实现、平台运行或因子有效性的源码及运行证据。不得据本文将任何阶段记为已验收。

包内依据：[项目概览](references/README.md)、[开发路线](references/ROADMAP.md)、[阶段验收规范](references/ACCEPTANCE.md)、[完整路径用例](references/FLOW_ACCEPTANCE.md)。这些规范说明目标与门槛；只有准确版本上的实际证据才能证明达成。

## 1. 审核任务与启动条件

审核者负责核对规范、独立设计边界和故障测试、复算关键指标、验证平台链路并给出绑定版本的结论。Codex 负责生产代码实现、自测与修复。审核者只在独立审核副本中新增测试和报告，不直接修改生产源码，也不替开发者重新定义经济晋升标准。

开始前取得：阶段规范、完整固定源码或可访问的提交、代码与配置哈希、环境和依赖版本、数据或合成夹具及许可说明、复现入口、独立标准答案、原始日志、平台项目与任务清单、候选谱系、预算和已知限制。核验实际文件、执行环境及 QuantConnect／LEAN 工具权限；不得假定已继承开发聊天的文件、工具或上下文。

缺材料时列明缺口和补验方法。本文现阶段的软件实现结论为 INCOMPLETE；平台执行项为 NOT_RUN，确实不适用才记 NOT_APPLICABLE；需要经济评估的项目为 NOT_EVALUATED。没有创建评估任务时，不虚构任务编号或执行状态。仅审阅规范可记 STATIC_ONLY，不能写成系统运行通过。

## 2. 状态与证据口径

每个测试项区分 EXECUTED、STATIC_ONLY、NOT_RUN，并记录输入、方法、实际结果和原始证据位置。运行了合成测试，不等于执行了真实平台测试；读过 Codex 日志，不等于独立重跑。

| 结论维度 | 可用状态及约束 |
|---|---|
| 工程实现 | PASS／FAIL／INCOMPLETE，依据本阶段要求和实际证据 |
| 平台集成 | PASS／FAIL／NOT_RUN／NOT_APPLICABLE，真实集成通过需真实任务与结果 |
| 因子经济证据 | SUPPORT／REJECT／INCONCLUSIVE／NOT_EVALUATED／NOT_APPLICABLE，不能从工程通过推导 |

适用的评估任务另记执行有效性：

| 状态 | 含义与允许结果 |
|---|---|
| VALID | 输入、运行、结果和版本完整有效，按预登记规则产生 SUPPORT、REJECT 或 INCONCLUSIVE |
| ERROR | 代码、数据或版本校验错误，经济结论保持 NOT_EVALUATED |
| INCOMPLETE | 已知必要任务或结果未齐，经济结论保持 NOT_EVALUATED |
| UNKNOWN | 无法确认提交或执行状态，先核实已有任务，经济结论保持 NOT_EVALUATED |

INCONCLUSIVE 仅表示有效评估后的经济证据不足。缺必要数据、代码故障、未完成任务和版本错配不能伪装为因子无效或统计不足。工程 PASS、阶段 ACCEPTED、候选经济晋升和真实资金部署分别判定。

## 3. S0 至 S7 逐阶段审核

下表是待执行任务，当前全部缺少系统执行证据。每阶段按依赖验收；基础接口未通过时，下游不得据模拟替代结果标为正式集成通过。

| 阶段 | 审核目标与独立方法 | 要求取得的证据 |
|---|---|---|
| S0 协议与骨架 | 核对市场、股票池、标签、调仓、基准、成本、风险、预算、停止和晋升规则；运行配置校验，构造缺字段和时间冲突反例 | 固定协议、接口、环境、最小入口、配置错误输出、版本关联清单 |
| S1 因子引擎 | 用手算数据复核算子、因子和标签；扰动未来数据、截断历史、检查非法引用；对齐批量与逐期结果 | 标准答案、输入输出、容差、拒绝记录、特征与标签隔离证据 |
| S2 时点数据与平台 | 抽查原始字段、历史成员、证券身份、公司行动、时区、复权和可用时间；尝试越界查询及任务中断 | 真实小样本、来源和数据版本、任务编号、访问拒绝、恢复及缓存记录 |
| S3 Research | 独立重算 IC、RankIC、分层、换手及不确定性；检查按日期切分、成熟标签和仅在允许区间拟合预处理；复核随机对照解释 | 原始因子与标签序列、独立计算、滚动配置、对照及完整报告 |
| S4 LEAN | 检查信号之后成交、预热、退出和重叠持仓；抽样对齐 Research；从订单成交复算费用和净值，施加延迟、成本及风险反例 | 真实完成任务、源码配置、订单成交、对账、成本和风险限制实际生效的记录 |
| S5 GPT 闭环 | 检查规范输出和真实数值来源；输入非法字段、越界、超深及超预算请求；复现失败反馈、检索和下一轮提案 | 请求响应、模型提示词版本、审计、真实评估、谱系、记忆、预算和停止记录 |
| S6 搜索与组合 | 检查结构及绝对相关去重；固定模型测因子、固定因子测模型；复算增量和消融；核查全配置计数及 S6.4 | 全部候选、收益序列、模型比较、消融、诊断假设、复验和停止记录 |
| S7 冻结与维护 | 核对冻结清单、受控最终测试、晋升和归档分支；验证前向对账、健康检查、模型切换和回退 | 不可变发布包、隔离审计、允许动作、用途标识、前向日志和故障演练 |

参考计算尽量不调用被审指标函数，避免同源错误。统计对照依预登记样本量和重复规则解释，不能要求每次随机 IC 恰为零。没有找到有效因子可与工程通过并存；未完成真实平台链路则仍缺相应集成证据。

## 4. S6.4 与模型版本专项门禁

准备冻结的最终配置必须覆盖代码、数据口径、股票池、公式与算子、预处理、特征顺序、标签与评价协议、模型训练、组合、风险、交易及成本。任一相关项改变，受影响的旧证据失效，返回对应审计、Research 和 LEAN 开发复验。

最终组合必须具有自身的含成本 LEAN 证据、对账和必要压力测试。分别通过的单因子不能代替组合资金和风险验证。尝试用配置 A 的任务结果冻结配置 B 时必须拒绝；未受影响证据的复用须说明版本及理由。仅任务已接受、证据缺失或预算不足均不能放行，最终测试不能补做开发验证。

固定模型核对同一模型工件、清洗器和特征顺序。滚动模型冻结初始工件及训练、参数选择、特征处理和更新准入规则，逐窗口核对合法训练截止时间、成熟标签和模型谱系。按冻结规则产生且完成就绪校验的新工件可启用；改变规则或特征处理则新建版本并返回开发复验。未来训练权重不得回灌历史，未就绪更新不得启用，失败应能回退适用的已验证版本。

## 5. F01 至 F08 完整路径核查

每条用例均先填 NOT_RUN，执行后再附证据和结论。受控结果只能在 ENGINEERING_TEST 的独立命名空间验证分支，不能给正式候选写入经济结论。

| 用例 | 必须核查的行为与证据 |
|---|---|
| F01 正常路径 | 假设、审计、Research 快筛、LEAN、S6.4、冻结、最终测试和前向日志版本贯通；只有有效 SUPPORT 及必需工程平台项通过、版本合法匹配才允许 ECONOMIC_VALIDATION |
| F02 开发失败反馈 | 分别制造 Research 与 LEAN 不达标，保存失败并供下一轮检索；快筛失败不无条件进入 LEAN，LEAN 失败不冻结；停止后不再提交新研究任务 |
| F03 最终 REJECT | 在有效评估后归档，尝试启动候选经济验证应被拒绝；保留原结论，不自动改公式重试最终测试 |
| F04 最终 INCONCLUSIVE | 有效执行但样本或统计不足时归档，阻止自动改写 SUPPORT；新数据评估另建记录，技术故障不得混入 |
| F05 配置复验 | 改公式、模型、特征、权重、成本或订单后挂接旧证据，必须阻止冻结；组合超限也应拒绝；复验齐备后才能恢复 |
| F06 派生隔离 | 从记忆、提示词、向量检索、自动摘要和导出读取最终材料及其摘要，应保持拒绝；保存来源、访问及披露历史 |
| F07 用途分离 | 固定基准演练前向、切换和回退；合法滚动更新可启用，非法时间或规则变更被拒；禁止被拒候选改标签部署或混入演练收益 |
| F08 异常恢复 | 注入缺数据、代码错、只接受、未知提交、错版本和重复消息；经济结论仍未评估；已有任务可核实恢复，实际重试次数和费用照实计入 |

真实平台集成要独立取得真实完成任务。不要为了完成 F01 而强迫真实候选盈利，也不要把合成分支测试的 SUPPORT 当作真实晋升资格。

## 6. 最终测试、用途与信息隔离

最终测试仅在 S7.2 的受控协议下运行。最终原始数据、指标、图表、排名、逐候选结果、解释、评审意见、调参建议及派生摘要均存于独立审计区，不能进入开发记忆、生成提示词、检索索引、自动摘要或常规开发导出。检查这些限制由实际权限与程序执行，并以绕过反例留下证据。

编排器只接收发布包和任务编号、执行有效性及允许动作等最小控制信息，该信息也不进入研究记忆。负责人按协议查看材料，披露对象、内容及用途留痕。最终结果若用于改选方案，相关区间登记为已用于开发，不得重新命名为未见测试。

有效 REJECT／INCONCLUSIVE 归档该轮；技术异常进入核查或等待。预登记允许的同冻结配置基础设施重试保留原始失败、任务和访问记录；改变研究配置的新版本返回开发复验，重新判断测试历史。重复消息不重复记账，真实重试消耗必须保留。

前向经济验证登记 purpose = ECONOMIC_VALIDATION 及候选发布包编号。没有合格候选时，可另用预先固定基准或夹具登记 purpose = ENGINEERING_TEST 验收运行能力。独立演练不改变候选状态、不产生晋升资格，模拟成交也不能单独证明真实容量。
