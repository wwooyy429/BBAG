# BBAG 流程路径验收用例

本规范将流程图的节点和连线转化为端到端验收要求，配合 [开发路线](ROADMAP.md) 和 [验收规范](ACCEPTANCE.md) 使用。所有用例当前均为待实现、未执行；后续报告须登记实际版本和证据。

## 执行与证据要求

- 每次用例运行登记实验、候选或基准、代码、配置、数据或夹具版本、任务编号、执行方式、运行用途和原始证据。
- 合成数据或受控结果可以验证分支与权限逻辑，必须使用 ENGINEERING_TEST 和独立测试记录，不产生正式研究候选的经济结论或晋升资格。
- 真实 QuantConnect 或 LEAN 集成通过需要实际平台任务与结果；接口模拟和分支测试不能替代。真实经济证据由隔离数据及预登记协议产生，不能由测试夹具指定。
- 未运行项目记为 NOT_RUN。技术故障记为相应的执行异常状态，经济结论保持 NOT_EVALUATED。
- 无合格研究候选时，仍可用固定基准或夹具验收系统能力；不能为了通过用例而强制晋升被拒候选。

## F01 正常候选完整链路

**前置条件：**研究章程、数据边界和预算已登记，开发用数据可用；所用规则、夹具和评价来源在记录中明确。

**步骤：**GPT 生成假设和 FactorSpec，依次完成公式与时间审计、Research 快筛和含成本 LEAN 开发验证；S6 选择最终配置，S6.4 核验匹配的证据；冻结发布包；受控执行者完成最终评估；满足晋升条件后启动对应的前向运行与监控。

**预期行为：**每一步有相同候选谱系和准确版本；只有所需开发验证完成才可冻结；只有有效 SUPPORT 且必需工程和平台项通过、部署配置符合冻结发布包才可进入正式 ECONOMIC_VALIDATION。固定模型工件须匹配清单；滚动模型按冻结规则生成并验证的新工件可启用，记录谱系与合法训练截止时间。配置错配、规则擅改、未来数据使用或模型未就绪须阻止启动。

**证据：**候选规范、审计、Research 和 LEAN 原始结果、开发复验记录、冻结清单、隔离审计记录、允许动作、匹配的前向日志。

**说明：**用受控 SUPPORT 触发该分支时仅验收测试命名空间内的流转，不等于实际候选获得 SUPPORT。正式经济晋升另需真实独立评估证据。

## F02 开发失败反馈

**前置条件：**开发预算足够继续，失败仅来自开发区数据。

**步骤：**分别构造 Research 不达标和 LEAN 成本或风险不达标的情形；保存原始失败原因；下一轮检索对应记录并生成新提案；达到停止条件时结束。

**预期行为：**快筛失败不无条件进入完整 LEAN；LEAN 失败不进入冻结；成功与失败记录均可检索；新提案引用相关开发经验并登记变化。经济逻辑改变计为新配置，重复完成消息不重复记账；停止后不再继续提交任务。

**证据：**两类失败记录、检索返回、下一轮规范、父子候选关系、预算与停止记录。

## F03 最终拒绝归档

**前置条件：**准确冻结包已通过 S6.4，最终评估完整有效，但未达到预登记经济条件。

**步骤：**得到 VALID 与 REJECT，尝试调用该候选的前向经济验证入口。

**预期行为：**保存并归档原结论；前向经济验证被拒绝；不自动改公式或反复调用该最终测试。工程功能验收可另用固定基准演练，原候选结论不变。

**证据：**隔离审计结果、归档记录、拒绝晋升记录及无对应候选经济运行的证明。

## F04 最终证据不足归档

**前置条件：**最终执行有效，必要数据与结果齐备，但有效样本量或统计证据不足。

**步骤：**得到 VALID 与 INCONCLUSIVE，尝试启动前向经济验证或将其改写为 SUPPORT。

**预期行为：**归档本轮证据不足结论，拒绝自动晋升及结果改写。以后积累新数据需建立新评估记录，保留此前结论和使用历史。代码或数据故障不能借此状态隐藏。

**证据：**不足原因、样本与统计记录、归档及拒绝晋升记录。

## F05 最终配置复验

**前置条件：**配置 A 已完成开发验证，S6 产生配置 B。

**步骤：**分别改变因子参数、模型或训练规则、特征顺序、组合权重，以及成本或订单规则；尝试挂接 A 的结果冻结 B。另测试两个因子各自合格但组合后超过资金或风险约束的情形。

**预期行为：**识别不匹配及受影响证据，阻止 B 冻结；按影响范围重新审计、Research 和 LEAN。仅改变执行成本时可复用不受影响的因子计算，但最终组合必须具有自身含成本 LEAN 证据。未来训练的模型不能回灌历史；滚动训练按同一合法规则和逐窗口版本复核。

**恢复与反例：**B 的必要开发验证完成且符合条件后才可冻结；只收到任务接受、证据缺失、版本错配或预算不足时继续阻止。最终测试不能替代复验。

**证据：**配置差异、旧证据失效记录、新任务与结果、最终组合对账、冻结资格判定。未受影响证据的复用也需注明版本与理由。

## F06 最终信息与派生内容隔离

**前置条件：**隔离审计区包含最终数据、指标、图表、排名、解释和调参建议。

**步骤：**分别从开发记忆检索、生成提示词装配、向量检索、自动摘要和常规导出读取上述内容；再以派生摘要作为输入重试。

**预期行为：**内容及派生摘要保持隔离，开发侧不能取得；编排器只接收版本、任务、执行有效性和允许动作等最小控制信息，该信息不进入研究记忆。负责人披露按协议留痕。

**披露情形：**若最终结果已被用于修改或选择方案，保留披露与决策记录，标记相应区间已用于开发，不允许再次宣称为未见测试。

**证据：**隔离属性、访问拒绝日志、摘要来源、最小控制返回和披露历史。

## F07 工程演练与经济验证分离

**前置条件：**当前研究候选为 REJECT、INCONCLUSIVE 或 NOT_EVALUATED，另有预先固定的基准或测试夹具。

**步骤：**使用 ENGINEERING_TEST 演练前向数据、订单、对账、监控、切换与回退；按冻结规则生成合法滚动模型更新，再尝试擅改训练规则、使用非法训练截止时间或未就绪工件；尝试将同一被拒候选改标签部署，或把演练收益归入其经济证据。

**预期行为：**允许独立基准或夹具的工程演练；合法滚动模型可以切换，非法或未就绪更新被阻止，失败时回退至适用的已验证版本；禁止改标签绕过晋升、篡改原候选状态和混入经济证据。系统功能可以验收，研究候选结论保持不变。

**证据：**用途、基准或夹具编号、独立运行记录、切换与回退日志，以及拒绝混用记录。

## F08 技术异常与恢复

**前置条件：**在提交、运行或评估过程中可注入故障。

**步骤：**分别制造必要数据缺失、代码异常、只返回已接受、提交结果未知、版本错配、重复完成消息和恢复时读取旧任务。

**预期行为：**执行有效性为 ERROR、INCOMPLETE 或 UNKNOWN，经济结论为 NOT_EVALUATED；不生成 SUPPORT、REJECT 或统计 INCONCLUSIVE。核实已有任务后再决定后续动作，同一任务的重复消息不重复计入结果和预算，实际重试产生的执行次数与费用照实记账；所有原始失败、访问和恢复操作保留。

**恢复边界：**同冻结配置的基础设施重试遵循预登记协议。涉及公式、模型、预处理、训练或交易配置的修复产生新版本，返回受影响的开发复验并重新判定测试数据使用历史。

**证据：**故障注入位置、原始异常、持久状态、任务核实、预算、恢复及访问记录。
